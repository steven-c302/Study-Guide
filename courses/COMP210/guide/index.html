Lesson 4 · Variable Scope

Scope = where a name is valid. A local variable is valid within the block of statements in which it is declared (a loop body, a method body, an if block, etc.). Two rules: (1) the declaration must occur before the variable is used, and (2) parameter names are local variables whose scope is the method body.

Warm-up: True or False

T / FYou "declare" a variable in a scope, so "scope" is the correct word for the region a local variable is valid within.
Your practice quiz caught this exact nuance. A variable is valid within the block of statements (the block) where it's declared — "scope" names the concept, but the region itself is the block. You don't "declare in a scope."
T / FA method parameter is a local variable whose scope is the body of that method.
Parameters behave exactly like locals declared at the top of the method body.
T / FA variable declared inside a for loop body is still usable after the loop ends.
It falls out of scope when the block ends — the compiler will reject any use afterward.

Trace the scope

1public static void main(String[] args) {
2    int n1 = 1;
3    if (n1 < 5) {
4        int n2 = 2;
5        n1 = n1 + n2;
6    }
7    // ...
8}
Multiple choiceImmediately after line 5 runs, which variables are in scope and what are their values?
On line 5 both are alive: n1 becomes 1+2 = 3, and n2 = 2 is still in scope inside the if block. After line 6, n2 is gone and only n1 = 3 remains.

Fix the code

This does not compile because of a scope error. What's wrong, and how would you fix it?

1int total = 0;
2for (int i = 0; i < 10; i++) {
3    int sq = i * i;
4    total += sq;
5}
6System.out.println(sq);   // <-- ?
sq is declared inside the loop body (line 3), so its scope ends at line 5. Line 6 is outside that block → sq is undefined there → compile error. Fix: declare sq before the loop if you need it afterward, or print it inside the loop. Note i has the same problem — its scope is the loop header + body only.

Lesson 4 · Stack & Heap Memory

The JVM splits memory into two regions. Call Stack — holds local-variable (and parameter) values for the currently executing methods, arranged like a LIFO stack. Heap — large general memory where the objects themselves live, organized by address. A primitive's value on the stack is its simple value; an object variable's value on the stack is the object's address on the heap (e.g. @835).

Concept check

Heap
Stack
T / FWhen you store an array in a local variable, the stack frame holds the array's address, not the array's elements.
Primitives store their value directly; object/array references store a heap address. The elements live on the heap.
Multiple choiceWhat does the Garbage Collector do?
If an object on the heap loses all references, the GC reclaims that memory. Popping frames is the stack's normal behavior, not GC.
Multiple choiceWhy does the JVM partition memory into stack and heap?
Straight from the slides: partitioning targets both space and time efficiency.

Vocabulary: Call Frame

Call frame — the memory where local variables for a currently executing method live. When a method is called, a new frame is pushed; locals are added as declared and removed as they fall out of scope. When a method returns, its frame is popped and execution resumes in the caller.
T / FThe call stack behaves like a queue: first frame pushed is the first removed (FIFO).
The stack is LIFO — last in, first out. The most recently called method returns first. (Push/pop, not enqueue/dequeue.)

Lesson 4 · Recursion

Recursive function — a function that calls itself within its own body to break a task into smaller subproblems. Its body has base case(s) and recursive case(s).
Recursive call — when a method calls itself.   Base case — a branch that does not make a recursive call (stops it).   Recursive case — a branch that does make a recursive call (moves toward the base case).

public static int factorial(int n) {
    // Base case
    if (n == 0) return 1;
    // Recursive case
    return n * factorial(n - 1);

Divide & Conquer — trace recur(4)

The exact snippet from your practice quiz. A divide-and-conquer algorithm breaks a problem into subproblems, solves each, and combines the results.

public static long recur(int n) {
    if (n <= 1) return 2;
    return recur(n - 1) * recur(n - 1);
}
Fill inTotal new stack frames pushed when calling recur(4):
Count every call: recur(4)=1, recur(3)=2, recur(2)=4, recur(1)=8 → 1+2+4+8 = 15.
Fill inIts return value:
recur(1)=2 → recur(2)=4 → recur(3)=16 → recur(4)=16*16 = 256.

Iteration vs. Recursion — True or False

T / FRecursive solutions generally use more memory than iterative ones because each call creates a new stack frame.
True — every recursive call adds a frame. The trade-off: recursion is often more elegant/readable and fits recursively-structured data.

Lesson 5 · Why OOP?

    
OOP flips responsibility. In the non-OO TriangleStats, six loose doubles represent a triangle and the caller must pass them around and keep them valid. OOP formalizes that collective meaning as an object. Encapsulation: the object exposes ways to query properties and invoke behavior while hiding the details. The onus moves to the class developer to implement/validate; the application developer just uses the public methods.

Straight from your quiz & slide 26. A class is the blueprint/factory; each object (instance) is a product built from it, defined by the values of its fields (its state).

public class Point {
    private double _x;
    private double _y;

    public Point(double x, double y) {
        _x = x;
        _y = y;
    }

    public double distanceTo(Point other) {
        return Math.sqrt(Math.pow(other._x - _x, 2)
                       + Math.pow(other._y - _y, 2));
    }
}

Lesson 5 · Instance vs. Class Members

    
Instance fields/methods belong to each object — every instance has its own memory, and instance methods run on a specific instance (they can use this). Class (static) fields/methods belong to the class itself — shared by all instances, accessible without creating an object, and static methods have no this.

Lesson 5 · Objects, is-a, Object & null

    
Object is the universal reference type — every class is automatically a subclass of Object. An object has an is-a relationship with three things, so a reference can be typed as any of them. null is the universal reference value — any class variable can hold null.

Lesson 5 · Getters & Setters (JavaBeans)

    
Because fields are private, a class exposes controlled access through getter (accessor) and setter (mutator) instance methods. Setters are also where you re-run validation before changing state.

    

      
Fill in — JavaBeans signatures

      
The JavaBeans getter signature is
        
        while the setter signature is
        .

      
      
Answers: public T getP() and public void setP(T value) (slide 16). A getter returns the field's type (T) and takes no args; a setter returns void and takes the new value.

    

    

      
Real example from Triangle


public double[] getPoints() {
    double[] points = {_ax, _ay, _bx, _by, _cx, _cy};
    return points;
}

public void setA(double ax, double ay) {
    validatePoints(ax, ay, _bx, _by, _cx, _cy);
    _ax = ax;
    _ay = ay;
}

      

        
Multiple choiceWhy does setA call validatePoints before assigning?

        
        
        
        
Encapsulation puts validation in the setter, so no caller can push the object into an invalid state.

      

      

        
T / FGetters and setters should be declared static.

        
        
False — they read/write a specific instance's fields, so they're instance methods (they use this implicitly).
