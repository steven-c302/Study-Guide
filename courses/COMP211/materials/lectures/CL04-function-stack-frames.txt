Stack Frames
- The Stack:
- An area of memory used to manage function calls
- Stack Frame:
- Each stack frame is like a mini workspace for a function.
- It holds everything the function needs to do its job, including:
- Return Address: The location in the program to return to after the function finishes.
- Arguments: Values passed into the function.
- Local Variables: Variables declared inside the function.
3
[Slide 4]
Motivation
- Understanding stack frames helps you understand what is actually happening
when functions call other functions.
- It also explains several important programming concepts, including:
- Why local variables disappear when a function returns
- How nested and recursive function calls work
- Why returning a pointer to a local variable can cause problems
- How the program knows where to continue after a function returns
- Why very deep recursion can cause a stack overflow
- How debuggers display the call stack when a program crashes
4
[Slide 5]
Caller and Callee
- Caller: the part of the program that calls a function
- Callee: the function that is called
- How a Function Call Works
- The caller passes data (arguments) to the function
- The callee:
- Receives the arguments
- Executes its code
- Produces a result (return value)
- Control returns to the caller
5
[Slide 6]
Stack Pointer
- Stack pointer
- Holds the memory address of the current top of the stack.
- When a function is called, the stack pointer is adjusted to make room for
the new stack frame.
- When the function returns, it is adjusted back, effectively removing that
frame.

Fixed-Size Integers
- int can be different sizes on different systems
- Fixed-size integers are integers with guaranteed sizes, giving you control
over memory and value range.
- This makes code:
- More predictable
- More portable
- Better for memory-limited systems (like embedded devices)
- #include <stdint.h>

[Slide 40]
Fixed-Size Integers
Type Bits Used Bytes When to use
int8_t 8 bits 1 byte tiny values, sensors, raw data
int16_t 16 bits 2 bytes small counters, audio samples
int32_t 32 bits 4 bytes general-purpose numbers
int64_t 64 bits 8 bytes large counts, timestamps, big calculations

[Slide 50]
Process
- A process is a running instance of a program.
- A program is passive
- It is just code stored in memory
- A process is active
- It represents that program in execution, with its own memory, CPU state, and resources.

Preprocessor Directive
- When the preprocessor sees a #define, it replaces every occurrence of a
name with its defined value literally, as if you had typed it yourself.
- What this means for memory diagrams:
- The preprocessor directive is not stored in the stack, it ends up as part of the code.
