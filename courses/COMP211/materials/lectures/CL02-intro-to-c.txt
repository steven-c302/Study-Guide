A Brief History of Programming
- In the late 1950s, high-level languages began abstracting away the details
of hardware, focusing on logic and algorithms.
- Key Early Languages:
- 1957: FORTRAN (FORmula TRANslation):
- First widely adopted high-level language.
- Developed by IBM for scientific and engineering calculations.
- 1958: LISP (LISt Processor):
- Pioneered functional programming and symbolic processing.
- 1959: COBOL (COmmon Business-Oriented Language):
- Designed for business applications.
- Emphasized readability and portability.
- Became a standard for enterprise and financial systems.

[Slide 10]
High-Level Languages
- Most programming languages you’ve heard of are high-level programming
languages (Python, Java, C, C++).
- C is a compiled high-level programming language.
- To execute a compiled high-level programming language, the program is first
translated into assembly language by a compiler, then an assembler
translates the assembly language into machine code.
- Interpreted languages like Python are executed differently. We’ll talk more
about interpreted languages later.

handle common tasks like input/output, string manipulation, mathematical

End-of-File
51
#include <stdio.h>
int main() {
int c = getchar();
while (c != EOF) {
putchar(c);
c = getchar();
}
}
This program is a simple echo program. It reads characters from the standard input
until it encounters the end-of-file (EOF) marker, and it outputs each character as it
reads it. Essentially, it copies input to output, one character at a time.
EOF stands for End of File. It is a
special value returned by getchar()
when there’s no more input to read.
You signal EOF by pressing Ctrl+D (Linux/macOS) or Ctrl+Z (Windows) when entering input manually.
putchar() takes the character stored
in c and prints it to the output.
[Slide 52]
End-of-File
- EOF stands for End of File. It is a special value returned by getchar() when
there’s no more input to read.
- EOF is the reason that getchar() returns an int instead of a char
- EOF must be distinguishable from any valid character
- In the ASCII character set, all valid characters are encoded as integers from 0 to 255.
- If EOF were encoded as a char, it could potentially collide with valid character values.
- For example, if EOF were represented as 255 on a system where char is unsigned, it
would conflict with the ASCII value for the ÿ character.
