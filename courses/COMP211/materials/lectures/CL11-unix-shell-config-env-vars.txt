What does $ mean in instructions?
• When you see instructions like this:
• $ echo "hello, world"
• The $ is not part of the command.
• It represents the command prompt.
• The $ symbol tells you:
• “The computer is ready for you to type a command.”
• So:
• You do not type the $
• You only type what comes after it
7
[Slide 8]
Why do I sometimes see learncli$ instead of $?
• Different systems show different prompts.
• learncli$:
• learncli is the name of the container
• cece@mbp $
• Username: cece
• Machine name: mbp
• You can control what your shell prompt displays
• The shell prompt is controlled by a variable named PS1.
• You can see it with echo $PS1, and change it by setting PS1 to a new value.

Environment Variables
• An environment variable is a named value that a program can receive from
the environment in which it runs.
• Environment variables are commonly used to give programs information
about their configuration or surroundings.
• Example:
• export COURSE="COMP 211"
• If you start a program from this shell, that program can access the value of COURSE.

Read an Environment Variable
• In Bash, $ means “give me the value stored in this variable.”
• $VAR and ${VAR} both access the value of a variable. The braces make it
explicit where the variable's name begins and ends.
• Without the $, the above command would just print the literal text
14
$ echo $HOME
/home/student
$ echo HOME
home
$ echo ${HOME}
/home/student
[Slide 15]
Change a Variable
• You can assign a new value with =:
• learncli$ EDITOR=vim
• Don't put spaces around =.
• learncli$ EDITOR=vim # correct
• learncli$ EDITOR = vim # incorrect
• But at this point, EDITOR is only a shell variable.
• To make it an environment variable that programs launched from this shell
can inherit:
• learncli$ export EDITOR
• Or do both at once:
• learncli$ export EDITOR=vim
15
[Slide 16]
Modify an Existing Variable
• Sometimes you want to add to an existing value rather than replace it.
• Suppose:
• $ echo "$PATH"
• shows:
• /usr/local/bin:/usr/bin:/bin
• and you want the shell to also search $HOME/bin. You could write:
• $ export PATH="$PATH:$HOME/bin"
• Bash first expands $PATH and $HOME, producing something like:
• /usr/local/bin:/usr/bin:/bin:/home/student/bin

[Slide 17]
Remove a Variable
• Use unset:
• $ unset EDITOR
• Now:
• $ echo "$EDITOR"
• prints nothing.

What is a Child Shell?
• When you type:
• $ bash
• you start another Bash shell from inside your current Bash shell.
• We call the new shell a child shell, and the shell that started it is its parent.
• A child process inherits environment variables from its parent.
• However, ordinary shell variables are not passed to the child.
18
[Slide 19]
Child Shell
• When you're finished with the child shell, run:
• $ exit
• The child shell terminates, and you're back in the original parent shell.
• Remember, a shell is just a program. When you type bash, your current
Bash process launches another instance of the Bash program.
• That new Bash instance is therefore a child process of the original Bash
process.

Changes Are Not Permanent
• If you type:
• $ export EDITOR=nano
• you've changed the environment of your current shell. If you close that shell
and start a new one, your change may disappear.
• If you want Bash to make the change whenever you start an interactive shell,
you can put the command in ~/.bashrc:
• export EDITOR=nano
• Then a new Bash session will execute that command when it reads
.bashrc.

How to Modify Path
• Add a directory to the beginning
• export PATH="/home/student/bin:$PATH"
• Now the shell searches:
• home/student/bin, then existing PATH directories
• Putting a directory first gives programs there higher priority.
• Add a directory to the end
• export PATH="$PATH:/home/student/bin"
• Now the shell searches the existing directories first and /home/student/bin last.
27
[Slide 28]
Example
• Suppose:
• $ echo $PATH
• /usr/local/bin:/usr/bin:/bin
• Then:
• $ export PATH="/home/student/bin:$PATH”
• $ echo $PATH
• /home/student/bin:/usr/local/bin:/usr/bin:/bin

[Slide 29]
Be careful about removing existing contents!
• This:
• export PATH="/home/student/bin:$PATH"
• adds /home/student/bin while preserving the old $PATH.
• But this:
• export PATH="/home/student/bin"
• replaces the entire $PATH, which can cause commands like ls, cat, and grep to stop
being found.

Temporary $PATH Changes
• If you run:
• export PATH="$PATH:/home/student/bin"
• the change affects the current shell session.
• You can verify it with:
• echo $PATH
• But when you close the terminal and open a new one, the change is
generally gone.
32
[Slide 33]
Persistent $PATH Changes
• To make the change apply to future shell sessions, put the command in a
shell configuration/startup file.
• Example: adding a line to .bashrc:
• export PATH="$PATH:/home/student/bin"
• Then new applicable Bash sessions can load that setting. You can also
reload that file in the current shell with:
• source ~/.bashrc

[Slide 35]
.bashrc
• Your .bashrc is a configuration file for Bash. It contains commands that Bash
runs when you start a new interactive Bash shell.
• The file is located in your home directory:
• ~/.bashrc
• The . at the beginning of the filename makes it a hidden file, so it normally
won't appear with a plain ls. You can see it with:
• $ ls -a ~
35
[Slide 36]
.bashrc
• Your .bashrc can be used to customize how your shell looks and behaves.
For example, it might contain:
36
# Change the prompt
PS1="learncli$ "
# Create a shortcut
alias ll="ls -al"
# Set an environment variable
export EDITOR="vim"
# Add a directory containing programs to PATH
export PATH="${PATH}:${HOME}/bin"
[Slide 37]
Alias
• An alias lets you create a shortcut for a shell command.
• For example, if you frequently type:
• ls -al
• you could create an alias:
• alias ll='ls -al’
• Another practical one is:
• alias c='clear'
• Then:
• c
• clears the terminal.
37
[Slide 38]
.bashrc
• An important thing to remember is that .bashrc is not just a list of settings.
• It contains Bash commands. When Bash reads .bashrc, it executes those
commands.
• If you modify .bashrc, the changes generally won't affect a shell that's
already running. You can either open a new Bash shell or tell the current shell
to read the file again:
• $ source ~/.bashrc
• The source command tells Bash to read a file and execute the commands in that file in
the current shell.

Python Virtual Environments
• A Python virtual environment is an isolated environment for a Python project
that has its own Python executable and its own set of installed Python
packages.
• Why do we use them? Imagine you have two projects:
• Project A needs package version 1
• Project B needs package version 2
• If every Python project uses the same globally installed packages, these requirements
can conflict.

Creating a Virtual Environment
• The following creates a directory called .venv containing the virtual
environment.
• python3 -m venv .venv
• Then the following activates it:
• source .venv/bin/activate
• After activation, commands such as:
• python
• pip
• refer to the versions inside .venv.
44
[Slide 45]
Python Virtual Environments
• You can investigate this with:
• $ which python
• Before activation, you might see:
• $ /usr/bin/python
• After activation:
• $ /home/student/project/.venv/bin/python
45
[Slide 46]
What's actually happening?
• Activation modifies your shell's environment (most importantly, $PATH) so
that the virtual environment's bin directory comes before the directories
containing the system Python.
• A Python virtual environment generally doesn't contain a complete
independent copy of Python.
• The python inside .venv/bin is commonly a link to an existing Python interpreter,
rather than another full copy of Python.
• The virtual environment mainly provides an isolated location for the project's installed
packages.
