Working with memory
• How do you know if an individual row should be interpreted as a one-byte
value or if it is part of a larger number?
• You cannot tell just by looking at memory.
• Main memory is simply a sequence of bytes. It does not inherently contain information
about data types or boundaries between values.
• The meaning of a particular memory region (for example, whether those bytes represent
a character, an integer, or part of an array) comes from how the program and the
processor interpret it. That information is stored elsewhere (in variable declarations, data
type definitions, or other program metadata).
• When the CPU or a program accesses memory, it always specifies both:
• the starting address, and
• the size of the data to read or write.

Statically Allocated 2D Arrays
• Programs often access the elements of a 2D array by iterating with nested
loops. For example, the following nested loop initializes all elements
in matrix to 0:
13
#define NUM_ROWS 50
#define NUM_COLS 100
int main() {
int32_t matrix[NUM_ROWS][NUM_COLS];
int32_t i, j;
for (i = 0; i < NUM_ROWS; i++) {
// for each row i
for (j = 0; j < NUM_COLS; j++) {
// iterate over each column element in row i
matrix[i][j] = 0;
}
}
return 0;
}
