Platform-dependent vs Platform-independent
•Platform-dependent: Code or instructions that are designed to run on a
particular type of computer architecture (such as x86-64 or ARM).
•Machine-specific code may need to be modified or recompiled to run on a different
architecture.
•Example: A C program compiled into x86-64 machine code cannot run directly on an
ARM processor.
•Platform-independent: Code that can run on different types of computers or
operating systems without needing to be rewritten or recompiled for each
platform.
•Example: Java bytecode is platform-independent because the same .class file can run on
different systems, as long as each system has a compatible Java Virtual Machine (JVM).

JVM Benefits
•Portability
•The same compiled Java program can run on different operating systems without being
recompiled, as long as a compatible JVM is available.
•Memory management:
•The JVM automatically allocates memory for objects and uses garbage collection to
reclaim memory that is no longer needed.
•Performance optimization:
•The JVM can identify frequently executed code and compile it into optimized machine
code to improve performance.

Memory Management
•A big difference between Java and C is who is responsible for managing
memory.
•In C, the programmer explicitly allocates and frees dynamically allocated
memory.
•In Java, the programmer creates objects, and the JVM automatically reclaims
memory when those objects become unreachable.

The Garbage Collector
•Garbage Collector (GC): A component of a program's runtime environment
that automatically identifies and reclaims memory occupied by objects that
are no longer needed, allowing that memory to be reused.
•In Java, the garbage collector identifies objects that are no longer reachable
by the running program and reclaims their memory.
•After p = null, the Person object is no longer reachable (assuming no other
references to it exist), so it becomes eligible for garbage collection.
18
Person p = new Person("Alice");
p = null;
[Slide 19]
The Garbage Collector can slow down the program
•Garbage collection (GC) can slow down a Java program because the JVM
must spend time finding and removing objects that are no longer needed.
•This can affect performance in two ways:
•Pausing the program: Some garbage collection operations temporarily stop the program
while the JVM manages memory. These are called stop-the-world pauses.
•Using CPU resources: Garbage collection requires processing power to find unused
objects and reclaim their memory. This competes with the program for CPU time.

[Slide 20]
Reference Counting
•Reference counting is one of the simplest approaches to automatic memory
management.
•The idea is to maintain a count of how many references point to each object.
•When the reference count reaches zero, the object becomes eligible for
garbage collection. Java does not necessarily reclaim its memory
immediately.
20
Person a = new Person("Alice"); // 1 reference to Alice
Person b = a; // 2 references
a = null; // 1 reference
b = null; // 0 references
[Slide 21]
The Problem with Reference Counting
•Circular References
•The objects still reference each other, so their reference counts are nonzero
even though neither can be accessed by the program.
•Simple reference counting cannot reclaim this cycle.
•This is a major reason Java uses tracing garbage collectors instead.
21
Node a = new Node(); // Node A: 1 reference (a)
Node b = new Node(); // Node A: 1, Node B: 1 (b)
a.next = b; // Node A: 1, Node B: 2 (b, a.next)
b.next = a; // Node A: 2 (a, b.next), Node B: 2
a = null; // Node A: 1 (b.next), Node B: 2
b = null; // Node A: 1, Node B: 1
[Slide 22]
Mark-and-sweep
•Mark-and-sweep is a tracing garbage collection algorithm.
•A GC root is a starting point that Java's garbage collector uses to find objects
that are still in use.
•It works in two phases:
•Mark: Starting from GC roots, traverse references and mark every reachable object.
•Sweep: Examine allocated objects and reclaim those that were not marked.

Memory Management: C vs. Java
•C gives programmers more direct control over dynamically allocated memory,
but also makes them responsible for freeing it correctly.
•Java automatically manages object memory, reducing common memory
errors at the cost of some runtime overhead.
•Garbage collection automates memory reclamation, reducing the need for programmers
to manually free dynamically allocated memory. However, memory is not necessarily
reclaimed immediately when an object becomes unreachable.
