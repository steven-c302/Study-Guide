Input Buffering
• Input from stdin is stored in a buffer in memory before it is passed to your
program.
• When you type data at the terminal, it is not immediately delivered to the
program. Instead, it waits in the buffer until:
• The user presses Enter.
• The buffer is full
15
[Slide 16]
Output Buffering
• The text you send (e.g., using printf) is temporarily stored in a buffer.
• The buffer is flushed (output is sent to the terminal) when
• A newline character (\n) is encountered.
• The buffer is full.
• The program explicitly flushes it using fflush(stdout).

[Slide 17]
Debugging an Input-Handling Program in C Using VSCode
• What happens if you don’t include fflush() when debugging?
• Remember printf uses buffered I/O, meaning that the text you print is stored in an internal
buffer and is only sent to the terminal when the buffer is flushed (this happens when a
newline is printed, the buffer fills up, or the program ends).
• If you don’t call fflush(stdout) while debugging, you may not see your program’s output
immediately as you step through the code. This makes it harder to observe intermediate
states.
• Calling fflush(stdout) forces the buffer to be written out right away, making it easier to
follow the program’s execution.

[Slide 24]
Launch.json
• "type": "cppdbg" tells VS Code which debugger extension should
handle this launch configuration.
• cppdbg is the debug type provided by Microsoft's C/C++ extension. It tells
VS Code to use the C/C++ debugging system for this configuration.
• The C/C++ debugging extension acts as a debug adapter to communicate
with the actual debugger (GDB).
24
[Slide 25]
Launch.json
• "MIMode": "gdb" tells the C/C++ debug adapter that the underlying
debugger it should communicate with is GDB.
• The "MI" part stands for Machine Interface. GDB has a machine-oriented
interface that programs such as VS Code can use to control it.
• Importantly, GDB is the thing actually debugging your program. VS Code
provides the interface you interact with, while cppdbg acts as the middle layer
that allows VS Code to control GDB.

What is –c for?
• -c means execute a command
• Normally, if you run /bin/bash
• Bash starts a shell and waits for you to type commands.
• /bin/bash -c "some command” means
• Start Bash, execute "some command", and then exit.
• So your our configuration effectively does:
• /bin/bash -lc "\".../program\" < \".../test\""

Representing a Pixel
• A pixel's color can be represented using four channels: red, green, blue, and alpha
(RGBA). The red, green, and blue channels determine the color of the pixel, while
the alpha channel determines its transparency.
• Each channel is an 8-bit value, so it can range from 0 to 255 (0x00 to 0xFF). For
example:
• Red: 0xA5
• Green: 0x3C
• Blue: 0x72
• Alpha: 0xFF
• Since each channel requires 8 bits, all four channels can be packed into a single 32-
bit integer:
• 0xA53C72FF
• In this exercise, the channels are stored in RGBA order, with red in the most
significant 8 bits and alpha in the least significant 8 bits.

#include <stdio.h>
uint32_t makeColor(uint8_t red, uint8_t green, uint8_t blue, uint8_t alpha) {
uint32_t color = 0;
// Put red in hexits 7-6
color = color | ((uint32_t)red << 6);
// Put green in hexits 5-4
color = color | ((uint32_t)green << 4);
// Put blue in hexits 3-2
color = color | ((uint32_t)blue << 2);
// Put alpha in hexits 1-0
color = color | alpha;
return color;
}
int main(void) {
uint32_t result = makeColor(0xA5, 0x3C, 0x72, 0xFF);
printf("Expected: 0xA53C72FF\n");
printf("Actual: 0x%08X\n", result);
return 0;
}
