[Slide 6]
Compile Time vs. Run Time
• Compile time
• The period when your program’s source code is being translated into machine code by
the compiler.
• Happens before execution.
• The compiler checks syntax, types, and generates the executable file.
• Run Time
• Run time is the period when your compiled program is executing.
• Managed by the runtime environment and the operating system.
• Errors like division by zero, invalid memory access, or file not found happen at run time.

Stack vs. Heap
• Stack
• Automatically managed
• Stores function stack frames
• Memory is freed when a function returns
• Heap
• Manually managed by the programmer
• Used for dynamically allocated memory
• Memory remains allocated until the programmer explicitly frees it

Scope vs. Lifetime
• Scope
• Scope is a compile-time concept.
• The region of your code where a variable's name is valid
• Defined by curly braces { }.
• Lifetime
• Lifetime is a run-time concept.
• The actual span of time that the variable occupies a physical spot in your computer's
memory.
• Defined by where the variable is stored in memory.

[Slide 17]
Introducing: malloc
• malloc is a function defined in the C standard library that allocates a block
of memory in the heap at runtime.
• void* malloc(size_t size);
• It reserves a block of memory containing size bytes.
• It returns a pointer to the beginning of that block.
• If the system cannot provide the requested memory, it returns NULL.
17
[Slide 18]
malloc
• void *malloc(size_t size);
• You must include:
• #include <stdlib.h>
• Return type: void *
• A generic pointer to the allocated memory block
• Parameter: size_t size
• Number of bytes to allocate.
• Return value:
• Pointer to allocated memory on success.
• NULL if the allocation fails.

[Slide 35]
Free
• void free(void *ptr);
• Releases memory previously allocated by malloc(), calloc(), or
realloc().
• Prevents memory leaks by returning the memory to the system.
35
[Slide 36]
Memory Leak
• A memory leak happens when a program allocates memory on the heap but
never frees it with free() and then loses all references to that allocated
memory.
• Why memory leaks are bad
• The leaked memory remains allocated until the program ends.
• Repeated leaks cause heap growth -> program uses more and more memory.
• Over time, this can lead to slowed performance or system crashes due to running out of
memory.

[Slide 41]
Free: Important Notes
• Only call free() once on each allocated block.
• Never free memory that wasn’t allocated with malloc(), calloc(), or
realloc().
• After calling free(), the pointer becomes dangling.
• Dangling pointer: a pointer that points to a memory location that is no longer valid
• Freeing memory too early can cause use-after-free bugs.
• Use-after-free bugs: occurs when a program continues to use a pointer after the
memory it points to has already been freed.

• void* malloc(size_t size);
• It reserves a block of memory containing size bytes.
• It returns a pointer to the beginning of that block.
• If the system cannot provide the requested memory, it returns NULL.
• void free(void *ptr);
• Releases memory previously allocated by malloc(), calloc(), or realloc().

int* create_even_numbers(int count) {
// Allocate an array of 'count' integers on the heap
int* arr = malloc(count * sizeof(int));
// Safety check: Ensure malloc succeeded
if (arr == NULL) return NULL;
for (int i = 0; i < count; i++) {

return arr;
}

[Slide 45]
The Unknown Size Array
• The most common use for dynamic memory is when you don't know how
much data you'll have until the program is actually running
• (e.g., asking a user how many items are in their shopping list).
• If we used a normal array like int grades[10];, we’d be stuck with exactly 10.
malloc lets the lifetime of the array's size be determined at runtime.
• See example on next slide.
45
[Slide 46]
46
#include <stdio.h>
#include <stdlib.h>
int main() {
int n;
printf("How many grades do you want to enter? ");
scanf("%d", &n);
// 1. Allocate memory on the HEAP
// We request space for 'n' integers
int* grades = malloc(n * sizeof(int));
// ALWAYS check if malloc failed (if the computer is out of memory)
if (grades == NULL) return 1;
for (int i = 0; i < n; i++) {
grades[i] = i * 10; // Assigning some values
printf("Grade %d: %d\n", i, grades[i]);
}
// 2. Deallocate the array manually!
free(grades);
grades = NULL;
return 0;
}

Resizing Memory
• Sometimes you start with a small array and later need to resize the array to fit
more data.
• This is how ArrayList in Java or list in Python works under the hood!

[Slide 48]
realloc
• realloc() resizes previously allocated memory.
• ptr = realloc(ptr, new_size);
• Preserves existing data up to the smaller of the old and new sizes.
• May move memory to a new location if the current block cannot be extended.
• Returns NULL if reallocation fails (the original pointer is still valid).
• Commonly used for dynamic arrays that grow or shrink at runtime.
• Declared in <stdlib.h>

#include <stdlib.h>

Pointer Arithmetic
• For both stack-allocated and heap-allocated arrays, the compiler determines
the address of element i using the same basic calculation:
• Stack-allocated array: stack_arr[i]
• The address of element i is:
• base address of stack_arr + (i × sizeof(int16_t))
• Heap-allocated array: heap_arr[i]
• The address of element i is:
• base address of heap_arr + (i × sizeof(int16_t))
