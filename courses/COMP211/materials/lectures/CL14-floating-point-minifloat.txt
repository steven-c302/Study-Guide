Microfloat
• Microfloat is a simplified, made-up floating-point representation that uses
only four bits.
• The small number of bits allows us to easily explore design tradeoffs.
3
[Slide 3]
Key Idea: Design Tradeoffs
• There’s a tradeoff between
• The range: how large or small a number you can represent and
• The precision: how accurately you can represent numbers
• Both of which are constrained by the total number of available bits.
4
[Slide 4]
Key Idea: Design Tradeoffs
• More exponent bits
• increases the range of representable numbers
• but reduces the number of bits available for the significand, decreasing
precision.
• More significand bits
• increases the precision,
• but reduce the number of bits available for the exponent, decreasing the
range.

Bias
• With microfloat V1, V2, and V3
• We cannot represent values between 0 and 1
• This is because the exponent must be positive
• Solution: Subtract a fixed bias from the exponent
• Negative exponents allow us to represent values between 0 and 1
• For microfloat, the bias is 2
• This allows for a range of [-2, 1]

[Slide 10]
Bias
• Why do we use a bias instead of 2’s complement?
• Simplifies Comparison Operations
• With a biased exponent, larger numbers have higher bit values, and smaller numbers
have lower bit values, making it easy to compare them as unsigned integers.
• If two’s complement were used, negative exponents (which have leading 1s) would be
greater in unsigned comparison, breaking the ordering.

NaN (Not a Number)
• The result of undefined or unrepresentable operations
• Example operations that would produce NaN result
• 0/0
• ∞/∞
• −1
• log(−5)
• NaN propagates through calculations
• Ex: if x = NaN, then x + 5 = NaN
• Enables graceful handling of errors
• Helpful for debugging

Floating Point Rounding
33
[Slide 32]
What happens when a number cannot be represented?
• If a floating-point number cannot be represented exactly, the computer
generally stores the closest representable floating-point value instead.
• If the number is within the representable range, but not exactly representable
• It gets rounded to a nearby representable value.
• The number is too large
• If the magnitude exceeds what the floating-point format can represent, you get overflow.
• The value is encoded as infinity or negative infinity.
• The number is extremely close to zero
• You can get underflow where the value rounds to zero.

Floating Point Rounding
• We cannot represent -32 in minifloat because it is outside of the range of
representable values. In this case, the computer would encode negative
infinity.
• Minifloat value for -32: 0b1 111 0000 => negative infinity

[Slide 35]
Floating Point Rounding: 12.25
• Decimal: 12.25
• Binary: 0b1100.01
• Normalize: 1.100012×23
• Minifloat: 0b1. 10001
• But we only have 4 fraction bits. So 10001 does not fit exactly.
• The two closest representable values are:
• 1.10002×23 = 12.0 and 1.10012×23 = 12.5
• And 12.25 is exactly halfway between them.
• Using round-to-nearest, ties-to-even, we choose 12.0.
• So: 12.25→12.0

[Slide 37]
Floating Point Rounding: 5.3125
• Decimal: 5.3125
• Binary: 0b101.0101
• Normalize: 1.0101012×22
• Minifloat: 0b1. 010101
• But we only have 4 fraction bits. So 010101 does not fit exactly.
• The two closest representable values are:
• 1.01012×22 = 5.25 and 1.01102×22 = 5.5
• And 5.3125 is closer to 5.25:
• 5.3125 − 5.25 = 0.0625
• 5.5 − 5.3125 = 0.1875
• Using round-to-nearest, we choose 5.25.
• So: 5.3125→5.25

[Slide 48]
Implicit 1
• Remember, implicit 1 means more precision
• Not storing the leading one gives us room to store an extra bit in the significand
• But this also leaves a large gap between 0 and the smallest non-zero value
• Any result smaller than the smallest normalized number would underflow directly to zero
• Design trade-off
• Pro: Higher precision for the same number of bits
• Con: A large gap around 0
• Solution: Add Denormalized numbers
• Drop the hidden 1 to add values around 0
