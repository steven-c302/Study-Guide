RD03 reading notes - Dive into Systems 16.4 (functions in C) and the array/strings background in 16.5 - study notes written for this guide
C is imperative and procedural: programs are organized as functions, starting at main (Java organizes into classes and objects; a Java program with one class, no data members and only public static methods looks most like a C program).
A function definition is: return type, name, parameter list, body. A prototype (declaration) gives only the name, return type and parameter list. All functions must be declared before they are called (so the compiler knows the type information), which is why prototypes often sit above main. A function that returns nothing has return type void. A call looks like function_name(argument_list); arguments are expressions.
Arguments are passed by value: each parameter receives a copy of the argument's value, so changing a parameter inside the function is not visible to the caller (in the max example, x = y changes only max's own x).
The execution stack tracks active functions; each call creates a stack frame (activation record) holding the function's parameters and locals; it is pushed on call and popped on return. Only variables in the active frame are in scope. Functions break code into manageable pieces and reduce duplication; document each with what it does, each parameter, and what it returns.
Arrays and functions (16.5): pass the array name (its base address); the function can change elements of the caller's array, but scalar parameters like size are copies. Functions usually take a size parameter because the array does not tell the function its capacity.
