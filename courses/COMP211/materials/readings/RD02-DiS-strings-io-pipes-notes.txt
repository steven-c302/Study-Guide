RD02 reading notes - Dive into Systems 16.5 (strings), 17.12 (I/O redirection), 17.13 (pipes) - study notes written for this guide
Strings (16.5): C has no string type; a string is an array of char ending with the null character '\0'. To store "hi" you need capacity 3 (h, i, \0); "hello" needs 6. printf("%s") prints characters until it reaches '\0'. strlen returns the number of characters before the null (not the array capacity). If the array is not null-terminated, library functions run past the end (undefined behavior). strcpy copies up to and including the null and assumes the destination is big enough: unsafe if it is not, and the programmer is responsible for valid strings. Java hides these details; C does not.
I/O redirection (17.12): every process starts with three open streams: stdin (file descriptor 0, keyboard), stdout (1, terminal), stderr (2, terminal). A file descriptor is a positive integer referring to an open file; Unix treats devices like terminals as files too.
Operators handled by the shell: < redirects stdin; > (same as 1>) redirects stdout and overwrites; >> appends stdout; 2> redirects stderr; &> redirects both stdout and stderr to one file (shorthand for 1> file 2>&1). Examples: wc < quote; cat quote > another; cat blah 2> error_out; echo "Again:" >> another; cat blah quote &> err_out; grep teach < another 1> grep_out 2> grep_error. Redirections are processed left to right, so 2>&1 must come after the stdout target to follow it.
Pipes (17.13): cmd1 | cmd2 sends cmd1's stdout to cmd2's stdin with no intermediate file. Pipes chain: cat quote | grep th | wc. ls | wc counts lines/words/chars of ls output; ls | xargs wc runs wc on every file listed by ls.
