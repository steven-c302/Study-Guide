RD16 reading notes - Dive into Systems 2.4 (dynamic memory allocation) - study notes written for this guide
Programs use dynamic memory allocation to get memory whose size is only known at run time. Dynamically allocated memory lives on the heap. A local pointer variable (int *p; inside main) is stored on the stack, and the heap memory it points to is anonymous: it is not bound to a variable name. malloc(sizeof(int)) returns the base address of the allocated heap memory on success and NULL on failure, so the return value should be checked before dereferencing (dereferencing NULL can crash). The best way to allocate an array of 20 ints is arr = malloc(sizeof(int) * 20); arr then contains the base address of a contiguous block in the heap. d_array[i] works on a pointer because indexing is defined as offset plus dereference from the base address (d_array[i] is *(d_array + i)); *d_array = 8 stores 8 into element 0. After free(p), setting p = NULL helps catch accidental use-after-free (a crash on NULL dereference instead of silent corruption). free does not need the size because malloc stores metadata (such as the size) in a header before the block. When a dynamically allocated array is passed to a function, the base address (the pointer value) is passed, which is why functions taking arrays often also take a size parameter: so they know how many elements they can safely access.
